Date: 2026-09-29
Status: Approved

## Goal

Six student project ZIPs live in `/Users/alexb/Documents/AI Projects/`. Each becomes its own
public GitHub repository under the `alexbernaldo` account, named by topic (no `PW#`/`GROUP`
in the name). A seventh repo, `AI-Projects`, is a public hub whose README indexes the other
six grouped by area.

## Repository contents

Every project repo contains exactly:

- The extracted notebooks, **with outputs preserved** (GitHub renders them directly).
- A `.gitignore` excluding datasets, trained weights, research PDFs, and OS/zip noise.
- A `README.md` with: title, one-line description, dataset (name, source, size, link),
  approach, how to reproduce, and headline results.

The `.gitignore` used by every repo:

```
# Datasets
*.csv
*.json
data/
datasets/
*.parquet

# Trained weights / binary artifacts
*.keras
*.h5
*.pt
*.pth
*.pkl
*.joblib
*.onnx

# Research reports
*.pdf
*.docx

# Environment / OS noise
.DS_Store
__MACOSX/
.venv/
venv/
~$*
.ipynb_checkpoints/
```

A `.gitkeep`-free exception is **not** used; notebooks reference datasets by filename only and
the README states where to obtain them. This is required because:

- `GRU_best_model.keras` is 110 MB — above GitHub's 100 MB hard limit; the push would fail.
- `best_model_E1.keras` / `best_model_E2.keras` are 25 MB / 6 MB, and the two `.pt` embeddings
  are 22 MB / 20 MB. Reachable, but regenerated by training and not worth hosting.
- Datasets (`news_dataset.csv` ~120K rows, `world-data.csv`, `pokemons.json`, 59k images) are
  large or licensed. They are downloaded separately.

All six repos are **public**. `gh` is already authenticated as `alexbernaldo` with scopes
`gist, read:org, repo, workflow` over HTTPS.

## Hub repository

`AI-Projects` contains only `README.md` (plus this spec directory). The README is an index
grouped by area, each entry carrying: repo name as a link, one-line description, technique
stack, and headline metric.

Areas and members:

- **Classical Machine Learning** — `ML_Wine_Quality_Classification`,
  `SLDM_Air_Quality_Benzene_Regression`
- **Unsupervised Learning & Data Mining** — `SLDM_Country_Segmentation_SOM_KMeans`,
  `Data_Mining_Pokemon_Clustering`
- **Deep Learning & Computer Vision** — `DL_Computer_Vision_Emotion_Classification`
- **Natural Language Processing** — `NLP_News_Classification_SkipGram_Embeddings`

The hub README opens with a one-paragraph statement of what the collection is (university
coursework on statistical learning / data mining / deep learning) and a note that each repo is
an independent snapshot of a graded practical.

## Naming convention

Repo names are PascalCase, topic-first, with underscores, following the user-supplied example
`DL_Computer_Vision_Emotion_Classification`. The `DL_` / `NLP_` / `SLDM_` / `ML_` /
`Data_Mining_` prefixes carry the discipline so the hub can be read at a glance.

## Execution

1. Create a scratch extraction dir per source ZIP; unzip with `-j` semantics avoided — each ZIP
   is a single top-level folder matching the ZIP name, so it is extracted to
   `AI-Projects/<repo_name>/` and renamed.
2. Strip `__MACOSX/` and `.DS_Store` from the extracted tree.
3. Write `.gitignore` and `README.md` per repo.
4. `git init`, `git add -A` (respecting `.gitignore`), verify the staged file list contains only
   notebooks, `README.md` and `.gitignore`, then commit.
5. `gh repo create <name> --public --source=. --remote=origin --push --description "<one-liner>"`.
6. Create `AI-Projects` last, push the hub README, and verify all seven URLs resolve with
   `gh repo view` / `gh api`.
7. Leave the original ZIPs untouched in `/Users/alexb/Documents/AI Projects/`.

## Verification

- `git ls-files` per repo lists only `*.ipynb`, `README.md`, `.gitignore`.
- No staged file exceeds 100 MB.
- `gh repo view <name> --json name,url,visibility` succeeds for all seven, all
  `"visibility": "PUBLIC"`.
- The hub README's seven links (six siblings + self) resolve — verified with
  `curl -s -o /dev/null -w "%{http_code}"` against each URL.

## Out of scope

- No modifications to notebook code or outputs.
- No `requirements.txt` (user chose the plain notebook + `.gitignore` option).
- No deletion or modification of the source ZIPs.
- No Git LFS.
